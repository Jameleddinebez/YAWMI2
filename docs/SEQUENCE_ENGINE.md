# محرك التسلسل البيداغوجي (`:sequence-engine`)

## الفكرة
السجل (`List<LoggedAction>`) هو مصدر الحقيقة. الحالة (`SequenceState`) تُشتق بإعادة تشغيله عبر دالة نقية. لا يوجد «رقم مرحلة حالية» مخزَّن.

## الإجراءات (ما يفعله الأستاذ فقط)
`CompleteCurrent` · `CompleteMerged(n≥2)` · `RepeatCurrent` · `ExtendCurrent` · `SkipCurrent` · `NotHeld(reason)` · `RecordAssessment(kind, consumesStage=false)` · `Reorder(remaining)` · `StartNewCycle` · `Undo(targetId)`.

## القواعد الصارمة وكيف يضمنها الكود
| القاعدة | الضمان |
|---|---|
| لا تقدم تلقائي بالوقت/الجدول | المحرك لا يقرأ الساعة ولا الجدول؛ الحالة دالة في السجل فقط |
| غياب/إلغاء لا يستهلك مرحلة | `NotHeld` يزيد عدّاداً فقط |
| فرض/اختبار لا يستهلك مرحلة تلقائياً | `consumesStage=false` افتراضياً؛ لا يتحرك المؤشر |
| استقلال الأقسام والمواد | لكل `SequenceTimeline` سجله الخاص؛ لا حالة مشتركة |
| إعادة الترتيب لا تمس المنجَز | `Reorder` يقبل فقط تبديلة للمراحل **المتبقية** |
| Undo صحيح | حدث جديد يشير لهدفه؛ لا حذف من السجل؛ إعادة التشغيل تتجاوز الهدف |
| منع التكرار عند المزامنة | إزالة التكرار بالمعرّف؛ الترتيب حتمي `(timestamp, id)` |
| تعارض بين جهازين | الإجراء الذي صار غير صالح يُوسَم `conflictedIds` ويُتجاوز، لا يُفسد الحالة |

## ما لم يُنفَّذ بعد (المرحلة 4)
- تحويل `LoggedAction` ⇄ `LessonActionEntity` (type + payloadJson).
- واجهة «تسجيل الحصة» ولوحة تقدم الأقسام.
- سياسة المزامنة بين الأجهزة على مستوى Firestore.
